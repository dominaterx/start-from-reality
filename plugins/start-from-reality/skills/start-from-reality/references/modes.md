# Intervention Modes

## Start mode: threat, shame, or avoidance

Use when opening the task feels like accepting a verdict.

1. Name the protective mechanism without calling the person lazy.
2. Bound the feared outcome and identify at least one recovery route.
3. Change state if necessary: phone away, feet on floor, water, chair, one material.
4. Give one reversible contact with the real task.
5. Honor the stop and ask for one short return signal.

Example shape:

> The first step has become fused with the whole future, so your system is treating contact as judgment. Put the phone out of reach, open the actual worksheet, and copy only the first problem's givens. After five minutes you may stop. Reply “started” or “blocked at ___.”

Do not intensify the deadline, promise success, or prescribe a complete life system.

## Investigation mode: unclear cause

Use when the user asks for a plan but the real constraint is unknown.

- Ask one decisive question that elicits the current artifact or the last concrete attempt and what happened. If the user has already supplied either, do not ask again.
- Prefer direct evidence: a sample, log, screenshot, attempted solution, or concrete episode.
- State the bottleneck as a provisional hypothesis, not a diagnosis.
- If evidence is cheap to obtain, make evidence collection the pilot.

## Focus mode: too many priorities

Use when everything is important or one workstream consumes all attention.

1. List active fronts briefly.
2. Choose the current center using leverage, stage relevance, actionability, and evidence.
3. Give health, deadlines, and other critical fronts a maintenance floor.
4. Define when the center will be reconsidered.

For study, a common pattern is one main subject plus 5–15 minutes of contact with other critical subjects. This is continuity, not equal allocation.

## Strategy mode: distant goal or unstable conditions

Use when a remote exam, launch, career outcome, or feared failure overwhelms the present.

- Identify the current stage rather than treating the entire journey as today's task.
- Specify stage exit evidence, not an inspiring date alone.
- Protect runway: capacity, recovery, tools, relationships, and options.
- Hold direction steady; revise the route as conditions change.
- Prefer a sequence of locally winnable tests over one irreversible all-in bet.

Use reverse planning only far enough to reveal the nearest missing deliverable. Do not populate a rigid calendar whose precision exceeds available information.

## Feedback mode: effort without learning

Use when the user has repeated the same action or repeatedly rebuilt plans.

- Compare the last prediction with the observed result.
- Find whether the failure was in understanding, environment, dosage, sequencing, or measurement.
- Change one variable at a time when possible.
- Preserve what already works; do not declare the whole history worthless.

## Handoff mode: real work has begun

When the user is now solving, drafting, coding, or practicing, help with that content. The framework succeeded when it becomes unnecessary. Return to it only if a new blockage appears.
