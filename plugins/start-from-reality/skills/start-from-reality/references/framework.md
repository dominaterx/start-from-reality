# Reality-to-Action Loop

This is the detailed operating model. The loop combines a threat-aware entrance with reality-based analysis and iterative practice. It is not a linear ritual: enter where the blockage is.

## 1. Make action safe enough

The aim is not perfect calm. It is enough safety to contact reality.

Check:

- What imagined judgment or distant consequence has been attached to the first move?
- What part of the outcome is reversible, repairable, or survivable?
- What choice does the person still retain?
- What stop condition will actually be honored?

Useful moves include a recovery map, a physical transition of under five minutes, producer language, and usually a 5–15 minute contact with the real material. Rest and play can be protected inputs to quality work rather than prizes withheld until completion.

## 2. See the present situation

Build the smallest reality map that can change the decision:

| Field | Question |
|---|---|
| Result | What observable artifact or change is wanted? |
| Present | What exists now? What has already been done? |
| Time | What deadlines or stage boundaries are real? |
| Capacity | What attention, energy, knowledge, money, and support exist now? |
| Constraints | What cannot be ignored or changed immediately? |
| Attempts | What was tried, and what happened? |
| Unknown | Which missing fact could change the next move? |

Label each statement as a fact, interpretation, prediction, or unknown. When a user is the primary witness, investigate with them rather than treating them as an object to diagnose.

## 3. Select the principal tension

State candidates as tensions between a needed condition and the present condition. Example: “The next exercise requires identifying the distribution, but the notation is not yet recognized.” Avoid “I am bad at probability.”

Score candidates lightly from 0–2:

| Test | 0 | 1 | 2 |
|---|---|---|---|
| Leverage | Little downstream effect | Some effect | Unlocks several moves |
| Stage relevance | Later issue | Partly current | Defines the current stage |
| Actionability | Outside influence | Indirectly influenceable | Directly testable now |
| Evidence | Guess | Mixed signs | Repeated or direct evidence |

The highest total is a hypothesis, not a decree. Name what evidence would disconfirm it. Re-select when the stage or facts change.

## 4. Run the smallest useful pilot

A valid pilot meets four tests:

1. It touches the real object of work.
2. It leaves a visible artifact or observation.
3. It tests the main uncertainty or tension.
4. It has an explicit boundary.

Examples:

- Study: attempt one representative problem and mark the first exact point of uncertainty.
- Writing: draft the claim and one supporting paragraph for the hardest section.
- Software: reproduce one failing path with the smallest fixture.
- Personal workflow: use one real task to test a proposed intake rule before redesigning the whole system.

“Organize everything,” “research productivity,” and “make a complete plan” are not pilots unless the uncertainty being tested is specifically about organization, tools, or planning.

## 5. Inspect the result

Use four lines:

- I expected:
- I observed:
- The important difference was:
- Therefore the next test is:

Separate execution failure from hypothesis failure. A failed attempt can still be a successful pilot if it reveals the real constraint.

## 6. Revise and re-enter

Plans need both stability and movement:

- Keep the direction and current-stage definition fixed long enough to generate evidence.
- Change tactics when a threshold is crossed or a decisive assumption fails.
- End each work period by leaving the next material, location, and first verb visible.
- Do not repay missed hours. Re-enter from the latest known point.

For a long horizon, define only:

1. the final direction;
2. the present stage and its exit evidence;
3. the next pilot;
4. the review condition.

This prevents both fatalism (“the gap is too large”) and fantasy (“one heroic sprint will settle it”).

## Focus without neglect

When several domains compete, choose one center task for the current block or day. Give other essential domains a maintenance floor: the smallest contact that prevents loss of information, health, or continuity. A center is not permission to abandon the whole system.
